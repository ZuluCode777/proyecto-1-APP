# Installed skills

Two skill sets, selected for this repo rather than installed wholesale.

- **Engineering set** (`domain-modeling`, `tdd`, `diagnosing-bugs`, `prototype`,
  `codebase-design`, `grill-with-docs`, `setup-matt-pocock-skills`, `to-spec`,
  `to-tickets`, `triage`, `code-review`) — Matt Pocock's skills, copied from the
  Second Brain App repo.
- **pstack** (everything else) — from
  https://github.com/cursor/plugins/tree/main/pstack/skills.

## Why these

TransMiVoz is a small Next.js app (about 2400 lines) whose whole surface is
device APIs: microphone, camera, geolocation, compass and speech synthesis. It
was generated by v0 and has no tests, no docs and no issue history. The
selection follows from that:

| Need | Skills |
| --- | --- |
| Write down the domain (station, portal, route, blindness mode) and where route data should come from | `domain-modeling`, `principle-model-the-domain`, `grill-with-docs`, `codebase-design` |
| Prove the device-API features actually work | `create-verification-skill`, `maintain-verification-skill`, `principle-prove-it-works` |
| Keep the pure logic in `lib/` correct | `tdd`, `principle-fix-root-causes`, `diagnosing-bugs` |
| Guard the public `/api/agent` endpoint | `principle-boundary-discipline` |
| Every file in the repo is TypeScript | `typescript-best-practices` (auto-applies via `paths`) |
| Accessibility is the product, not a feature | `principle-experience-first` |
| Docs and course write-up | `technical-writing`, `unslop`, `teach`, `how`, `why` |
| Shape non-trivial work before coding | `architect`, `prototype` |
| Backlog, once there is a team or a graded backlog | `setup-matt-pocock-skills`, `to-spec`, `to-tickets`, `triage`, `code-review` |

## Notes

- The issue-tracker chain needs `/setup-matt-pocock-skills` run once before
  `to-spec`, `to-tickets` or `triage` will work.
- `create-verification-skill` writes its output to `.cursor/skills/`, which is
  pstack's convention. For Claude Code, point it at `.claude/skills/` instead.
- `domain-modeling` and `principle-model-the-domain` overlap. Both are here on
  request; `domain-modeling` is the one that produces files (`CONTEXT.md`,
  ADRs), `principle-model-the-domain` is a single rule to invoke mid-task.
- `code-review` here shadows the host's built-in `/code-review` command.
- Skipped on purpose: `wayfinder` and `implement` from the engineering set;
  `arena`, `swarm`, `interrogate`, `blast-radius`, `figure-it-out`,
  `no-comments`, pstack's own `tdd`, and the remaining `principle-*` skills
  that cover concurrency, idempotency and legacy-API migration — none of which
  this codebase has.
